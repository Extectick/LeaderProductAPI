# Диагностика приложения через API

`POST /api/diagnostics/app-errors` принимает JSON от вошедшего пользователя. Учётную запись API определяет по Bearer-токену. Для включения примените миграцию `20261124110000_app_error_report_details` и задайте `APP_ERROR_REPORTING_ENABLED=true` и `APP_ERROR_REPORTING_ENVIRONMENT=development` или `production` на соответствующем API. Отдельный флаг `APP_CRASH_REPORTING_ENABLED` управляет прежней интеграцией Sentry.

Отчёт содержит UUIDv4 события, время возникновения в UTC, категорию ошибки, источник, область приложения, этап экрана, платформу, доступные версии, идентификатор OTA, массивы имён компонентов и числовых координат стека. Для Android-источника `android_native` требуются одна из категорий `java_exception`, `native_crash`, `anr` и объект `nativeEvidence` с версией Android API. Объект может содержать класс исключения, до 16 Java-кадров, номер сигнала и код причины завершения. Полный контракт со списками значений находится в `src/modules/monitoring/appErrorReports.ts`. Для расшифровки позиций JS нужен source map конкретной сборки/OTA, а для обфусцированных Java-кадров — соответствующий mapping.

API ограничивает распакованное тело 8 КиБ и принимает только несжатый JSON. Он сохраняет отчёт в `AppCrashEvent` с проектом `leaderproduct-app-errors`. Каждая учётная запись может отправить 12 новых событий за час. Повторная отправка того же UUID от той же учётной записи возвращает 204 и сохраняет единственную запись. Временное ограничение даёт 429 с `Retry-After`, недоступность хранилища — 503. Фоновая задача ежечасно удаляет до 5000 событий старше 30 дней.

Администратор может читать `GET /api/diagnostics/app-errors?screen=orders&kind=maximum_update_depth`. Поддерживаются точные фильтры `screen`, `kind`, `source`, `stage`, `eventId`, `otaUpdateId` и `limit` от 1 до 100. Результат содержит массив `items` от новых к старым. Для следующей страницы передайте значение `nextCursor` в параметре `cursor` с URL-кодированием. Поле `details.eventId` соответствует номеру события на устройстве. Пустой результат означает, что подходящие отчёты ещё не поступали или уже вышли из срока хранения.
