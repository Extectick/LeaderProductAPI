## Причина

У НОУТ-115288/289/290/291/292/293/297 одинаковы appGuid, revision=3 и requestId.
Это один SUBMIT и семь серверных попыток. Первичная запись документа успевала сохраниться,
затем сбой инициализации модуля EmeWms прерывал обработку до записи связи с приложением.
Повтор видел отсутствие связи и создавал новый документ. Синтаксическая ошибка EmeWms
является отдельной причиной отказа проведения; данная защита не исправляет этот модуль.

## Изменения 1С

Версия ping: `clientOrdersApiVersion=2026-09-24-atomic-order-import-v51`.
Возможность: `clientOrderWriteProtocolVersion=atomic-order-import-v1`.

1. Исключительная управляемая блокировка регистра `ЗаказыКлиентовПриложения` по appGuid
   берется **до чтения** записи импорта, в том числе для еще отсутствующего ключа.
2. Простая запись заказа и квитанция импорта (ссылка, revision, payload hash) фиксируются
   одной транзакцией. Ошибка до COMMIT откатывает оба изменения.
3. Проведение идет отдельной транзакцией под той же блокировкой с повторной проверкой ревизии.
   При аварии проведения первая транзакция сохраняется: заказ уже имеет связь.
4. Повтор того же пакета возвращает тот же документ, в том числе непроведенный.
   Повторное проведение после исправления причины — явная отправка новой ревизии, не бесконечный retry.
5. Старая ревизия/другой payload той же ревизии отклоняется. Ошибка чтения существующего
   документа больше не превращается в `СоздатьДокумент()`.
6. POST, PUT по appGuid и регламентная pull-очередь используют общий защищенный импорт.
7. Прямой импорт не отправляет HTTP snapshot из подписки записи до COMMIT;
   после перечитывания объекта восстанавливаются признаки прямого импорта.
8. Отдельный режим GET `/client-orders/:appGuid?appGuid=...&importReceipt=true` читает
   связь именно по ключу приложения, ожидая текущую транзакцию. Обычный GET по GUID 1С не меняется.
   Ответ содержит `lastImportedRevision`, `importState`, `deletionMark`.

## Изменения API

- Перед повторной записью — чтение квитанции по appGuid, проверка организации, контрагента,
  ревизии, признака удаления и существующая проверка полного состава строк.
- Если 1С уже сохранила эту ревизию, API принимает результат через `GET_RECONCILED`, без POST/PUT.
- Неизменяемый `ORDER_EXPORT_PACKET` сохраняет requestId и подтвержденный при первой попытке
  `writeProtocol`. Только изначально защищенный пакет можно автоматически повторить после 404.
- Для старого незащищенного пакета 404/неподтвержденная квитанция НЕ доказывает отсутствие заказа.
  Автозапись останавливается: `syncState=ERROR`, `ONEC_WRITE_RECONCILIATION_REQUIRED`, `willRetry=false`.
  Сетевой сбой сверки не разрешает запись; читающий повтор остается с backoff.
- Проверка истории идет по всем ревизиям: новая кнопка отправки/редактирование не обходят
  незавершенную старую попытку. Новый пакет не сохраняется до разрешения предыдущей неопределенности.
- PostgreSQL advisory lock, существующий CAS и запрет менять requestId при retry сохранены.

Старые неподтвержденные пакеты нельзя автоматически признать безопасными только потому,
что расширение уже обновили. Исторические дубли и потерянные связи проверяются отдельно,
без сопоставления по одной сумме/дате/контрагенту.

Обязательная проверка после загрузки в тестовую базу, до production:

- Ошибка записи регистра до первого COMMIT: нет ни нового заказа, ни связи.
- Ошибка/падение процесса после первого COMMIT: один непроведенный заказ и связь;
  повтор идентичного пакета возвращает его же, история не содержит второй create.
- Потеря HTTP-ответа после успешного проведения: один документ; API выполняет только сверку.
- Два параллельных POST, а также POST одновременно с pull-очередью: один документ.
- Новая ревизия, старая ревизия, другой payload с той же revision; отмена и повтор отмены.
- Ошибка чтения/физическое удаление связанного документа: новый не создается.
- НДС/проведение с ошибкой, счет и snapshot не должны подтверждать незакоммиченные изменения.

При развертывании сначала остановить обработку старых сомнительных пакетов и проверить их,
затем установить/проверить v51 и выпустить API. Приложение/OTA/APK для этой защиты не требуются.
