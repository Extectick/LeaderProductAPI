# Геомаршруты v2

## Назначение

`tracking_v2` заменяет старую связку Expo Location + `LeaderTrackingService` на Traccar Client SDK. Координаты буферизуются нативно на устройстве, а фоновая отправка не зависит от срока жизни пользовательского JWT.

1С в обмене геоданными не участвует. Точки, маршруты и координаты заказов хранятся в LeaderProduct API.

## Включение

- применить миграцию `20260904120000_tracking_v2`;
- задать `TRACKING_V2_ENABLED=true` в API;
- выпустить новый APK: Traccar и MapLibre являются нативными зависимостями;
- включить сервис `tracking` и нужные права ролям;
- в приложении при необходимости задать `EXPO_PUBLIC_MAP_STYLE_URL`;
- включать пилотных пользователей только после установки нового APK.

Новые маршруты API добавочны. Старые `/tracking/native-token`, `/tracking/native/points` и `/tracking/admin/...` остаются для ранее выпущенных APK.

## Безопасность

- `/tracking/device/bootstrap` выдаёт случайный credential только для записи координат;
- в БД хранится SHA-256 credential, исходное значение хранится устройством через Android Keystore;
- credential не даёт доступа к чтению данных и другим методам API;
- при паузе запись блокируется, при выходе credential отзывается через
  `DELETE /tracking/native/device`; неуспешный офлайн-отзыв остаётся в
  защищённой очереди устройства и повторяется при следующем запуске;
- пользователь берётся из credential или пользовательской сессии, `userId` от приложения не принимается;
- координаты и точные геособытия очищаются через `TRACKING_RETENTION_DAYS` (по умолчанию 180 дней).

## Основные методы

- `POST /tracking/device/bootstrap` — регистрация или восстановление устройства;
- `DELETE /tracking/device/bootstrap` — отзыв устройства при выходе;
- `PATCH /tracking/device/status` — пауза/возобновление;
- `POST /tracking/native/osmand` — приём формы Traccar;
- `DELETE /tracking/native/device` — идемпотентный самоотзыв credential;
- `GET /tracking/users` — сотрудники в доступной области RBAC;
- `GET /tracking/users/:userId/live` — короткий запрос последней точки;
- `GET /tracking/users/:userId/day?date=YYYY-MM-DD&eventCursor=...` — упрощённая линия,
  остановки и курсорная страница заказов за сутки;
- `POST /tracking/users/:userId/location-requests` — запрос свежей позиции;
- `GET /tracking/location-requests/:id` — состояние запроса.

## Диагностика

На устройстве профиль показывает состояние разрешений, GPS, работу трекера и последние записи SDK. Постоянное Android-уведомление подтверждает работу foreground service. После Force Stop Android не разрешает автоматический перезапуск до ручного открытия приложения.

Для серверной диагностики проверять:

1. `TrackingDeviceToken.lastUsedAt` — поступают ли точки с устройства;
2. `RoutePoint.serverPointKey` — защита от дублей;
3. `TrackingLocationRequest` — запросы текущей позиции;
4. `OrderGeoEvent` — координаты создания и отправки заказов;
5. логи с префиксом `[tracking-v2]`.

Credential нельзя писать в логи, тикеты или скриншоты.

## Приёмочные сценарии

- движение при открытом, свёрнутом приложении и выключенном экране;
- перезапуск процесса и телефона;
- не менее восьми часов с нестабильной сетью;
- офлайн-накопление и последующая догрузка без дублей;
- пауза, выход, повторный вход и повторная привязка устройства;
- GPS/разрешения/уведомления выключены;
- создание и отправка онлайн- и офлайн-заказа;
- ручной запрос позиции при активном и фоновом приложении;
- проверка видимости: сотрудник — себя, руководитель — отдел, администратор — всех.
