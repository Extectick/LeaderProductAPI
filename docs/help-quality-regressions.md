# Проверка качества ответов Help

Обновлено 6 ноября 2026. Это техническая реализация, а не автоматическое обучение весов модели или публикация новых правил компании.

`npm run test:help-quality` проверяет контекст, историю IT, контракты ответов, исправление оформления, результаты инструментов и readback. Тесты используют синтетические ответы и mock-транспорты; реальные сервисы и ключ OpenAI не требуются. Workflow `help-quality-check.yml` запускает их на изменениях Help в dev/PR. Отдельные реальные модельные пробы остаются явной dev-проверкой, а не обязательным платным шагом CI.

| Case | Регрессия |
| --- | --- |
| `help.it-departure-followup` | IT_LEFT и последующая реплика владельца используют каноническое состояние и оригиналы сообщений. Причина/местонахождение специалиста неизвестны. Уход сам по себе не вызывает ИИ. |
| `help.it-message-provenance` | Реплики IT читаются как реплики IT, не становятся целями, решениями или правами владельца. Вложения остаются owner-scoped. |
| `help.handoff-single-instruction` | Одна инструкция кнопки в первом предложении, причина сохраняется. Повторная инструкция убирается; явная просьба пользователя может объяснить действие снова. |
| `help.answer-presentation-repair` | Одна корректирующая попытка JSON/schema/citations с `tools=[]`, `tool_choice=none`. Повтор чтений, файлов и записей запрещён, свежие ACL сохраняются. |
| `help.no-write-replay` | После попытки изменения ошибка пояснения завершает run без автоматического повтора всего задания. Redis-журнал продолжает защищать повторные явные вызовы. |
| `help.partial-is-not-empty` | Partial/unavailable/forbidden/unknown не означают отсутствие данных. Пустой результат требует успешного полного чтения конкретной области. |
| `help.scoped-write-readback` | Для фиксированных поддержанных операций — максимум один точный GET от того же сотрудника, с ACL до/после. Подтверждаются только checkedFields; неизвестная запись не становится принятой. |
| `help.immediate-danger-emergency-route` | Общий экстренный маршрут при непосредственной физической опасности имеет приоритет перед IT; без диагноза, лекарств и объявления уже вызванной помощи. |

Классификацию и дальнейшие действия по замечаниям хранит приватный `issue-queue/followup.json`, связанный с проверенным оператором `followup-plan.json` и хешами доказательств. Существующие NEW/CONFIRMED/FIXED/VERIFIED/DISMISSED меняются только trusted triage с ожидаемым статусом. Отчёт сам ничего не исправляет, не запускает код и не повышает статус.

Обращения IT и качество ответов сотрудника выделены в HUMAN_COMMUNICATION. Исторический ERROR/STOPPED не доказывает текущую ошибку; отсутствующие старые tool bodies остаются UNKNOWN. Старые формулировки замечаний не закрываются только по похожему новому тесту.

Оценки/закрытие из существующего source-контракта используются как сигналы анализа. Они не доказывают успешное решение. Для новой инструкции остаются обязательными полная CLOSED-переписка, явное положительное OWNER/IT подтверждение и ручной review/publication в Nextcloud. Дополнительные всплывающие оценки в APP не добавляются.
