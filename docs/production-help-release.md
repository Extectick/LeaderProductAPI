# Production Help schema and release

Production keeps its own `LeaderAPI` users, tickets, personal connections and
knowledge ACL. Do not copy development conversations, credentials, learning SQLite
or analyzer schedules. Real Help responses use server-side OpenAI configuration;
enabling the assistant does not enable the scheduled analyzer.

## Schema gate

`scripts/apply-production-help-schema.cjs` is a production-only, atomic additive
chain of nine pinned migrations. It creates 23 Help/knowledge/personal connection
tables and registers Help/knowledge permissions without assigning roles. It does
not run historical Prisma migrations, `db push`, seed or destructive SQL.
`--plan` (`--dry-run`) and `--verify` use read-only transactions. `--apply` takes
the shared migration advisory lock, executes all nine migrations and records their
SHA-256 checksums in `HelpSchemaVersion` in one transaction. Any failure rolls back
DDL and registrations together. A partial or unrecorded pre-existing schema is
rejected for manual investigation, never silently adopted.

Required environment, in addition to the private production `DATABASE_URL`:

```text
NODE_ENV=production
DB_ACCEPT_DATA_LOSS=0
HELP_MIGRATION_TARGET=prod
HELP_MIGRATION_DATABASE_CONFIRM=LeaderAPI
```

Take and validate a PostgreSQL backup before applying. In the candidate image,
with the production network and private env explicitly provided by the operator:

```sh
node scripts/apply-production-help-schema.cjs --plan
node scripts/apply-production-help-schema.cjs --apply
node scripts/apply-production-help-schema.cjs --verify
```

Only `LeaderAPI`, public schema and matching live database identity are accepted.
The full catalog contract checks types, nullability, defaults, generated columns,
foreign keys/checks, index definitions and index validity; it includes SQL-owned
audio/mail tables and the knowledge generated tsvector. Existing permanent public
order links require nullable `OrderShareLink.expiresAt`; the gate refuses a schema
that would break them. Other pre-existing application tables are not changed by
this migration. Core schema compatibility must also be reviewed for each release.

`production-help-schema.contract.json` was generated by applying the exact pinned
SQL transaction to an isolated restore of the production **schema-only** dump on
PostgreSQL 16 and reading `catalogSql` from the migrator. Keep this contract and
`production-help-migrations.json` versioned together. Changes to either require
review and rerunning the isolated test; do not regenerate them from a live database
merely to bless drift. Migration SQL hashes normalize CRLF to LF.

API startup uses `DB_INIT_MODE=verify-production` with the same explicit gate
environment. Startup only verifies; apply migrations before replacing the healthy
API. Automatic production `db push` and startup `migrate` are forbidden. The generic
Prisma diff gate cannot replace this gate because audio/mail tables and generated
knowledge columns are intentionally SQL-owned.

## Service configuration

Compose order is base `compose.yml`, production `compose.s3.yml`, optional
`help-production.private.json`, then `release-image.json`. The image overlay pins
`api`, `help-assistant-worker`, and `knowledge-worker` together. It must preserve
provider flags, key mounts, healthchecks, S3 configuration, order auto-submit and
permanent share flags. Restricted OpenAI/Expo proxy sidecars keep their own images.
The image-only deployment helper rejects configuration drift; bootstrap of a new
private binding is an explicit separate operation, not an image-only update.

Require healthy API and both workers, with healthchecks asserting real OpenAI
Sol/medium and secret readiness. In production general diagnostics requires BOTH
`HELP_OPENAI_ALLOW_GENERAL=true` and `HELP_OPENAI_ALLOW_GENERAL_PRODUCTION=true`.
It does not weaken per-source ACL, personal 1C permissions, request grounding,
lease or explicit IT confirmation. Keep knowledge publication manual until
individual published document ACL mappings are reviewed. Never auto-publish
private IT material or grant all employees access as part of indexing.

## Verification

Run `node --test scripts/test-production-help-schema.integration.cjs` for guard
tests. Full integration requires `PROD_SCHEMA_SYNTHETIC_TEST=yes` **inside an
isolated test network namespace** containing a fresh schema-only `LeaderAPI` on
loopback. The test deliberately mutates only that disposable schema. It verifies
dry run, atomic rollback after a late failure, idempotency, checksum drift,
column/default/index/constraint drift, preservation of existing table columns and
absence of implicit role grants. No production URL is accepted by the test.
