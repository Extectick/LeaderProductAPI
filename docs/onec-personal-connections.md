## Для сотрудника

В приложении: **Профиль → Подключение 1С**. Форма показывает базу, имя пользователя 1С, отдельный логин входа, состояние подключения и поле пароля. Логин и имя берутся по точному сопоставлению GUID; ФИО не используется как логин. Для существующих 31 сопоставленных пользователей dev заполнены оба значения.

Полное имя берётся из `ПользователиИнформационнойБазы.ПолноеИмя`, с резервным значением `Справочники.Пользователи.Наименование`, когда полное имя пустое. Логин — `ПользователиИнформационнойБазы.Имя`. Связь проходит через `ИдентификаторПользователяИБ`. Это разные поля, даже если их значения иногда совпадают.

При отсутствии сопоставления пользователь вводит логин самостоятельно. Неизвестное имя не придумывается; показывается «Не сопоставлено». Для новых GUID необходимо обновлять административный каталог — непрерывная синхронизация этого каталога пока не подключена. Импорт не получает и не устанавливает пароли сотрудников.

После ввода пароля сервер проверяет авторизацию MCP. Можно обновить пароль или отключить подключение. Отключение удаляет сохранённый пароль, сохраняя логин и имя для следующего подключения. Смена GUID автоматически отзывает старые реквизиты.

Если OpenAI при работе с обращением запрашивает 1С без действующего подключения, сервер сохраняет ответ с действием `connect_onec`. APP показывает кнопку **Подключить 1С**, открывает эту же форму и после успешного подключения повторяет остановленную задачу в исходном чате. Пароль не отправляется сообщением. Возобновление разрешено только владельцу обращения и актуальной задаче.

## Хранение и границы доступа

- `OnecConnection`: ключ `(userId, baseKey)`, `boundGuid`, шифротексты логина, имени и пароля, источник логина, время проверки, ревизия и счётчик попыток.
- `OnecDirectoryEntry`: административный каталог `baseKey + GUID`, GUID пользователя информационной базы и раздельные шифротексты логина/полного имени.
- AES-256-GCM; случайный nonce для каждой записи. AAD включает пользователя, базу, адрес сервера, GUID и назначение поля. Перенос шифротекста другому пользователю/базе не даёт доступа.
- Ключи находятся в отдельном файле на VDS, доступны API и Help worker только через read-only mount. Их нет в Git и в PostgreSQL. Сохранить отдельную защищённую резервную копию keyring: одна резервная копия БД недостаточна для восстановления секретов.
- APP не сохраняет пароль в SQLite, AsyncStorage или истории; поле очищается при отправке, уходе со страницы и сворачивании приложения. Сервер не возвращает пароль. Логин/имя возвращаются только самому пользователю.
- API проверяет сотрудника и его блокировку по актуальной БД. Нельзя передать чужой `userId`, другой URL MCP или привилегированный режим. Изменение аккаунта в APP прекращает запросы, привязанные к прежнему пользователю, включая повтор после обновления токена.
- PUT требует HTTPS. За TLS-прокси заголовок `X-Forwarded-Proto` принимается только от перечисленных адресов прокси. Роут обрабатывается до body-логирования Kafka/debug/audit, ошибки не содержат тело запроса или диагностику 1С. Все ответы имеют `Cache-Control: no-store`.
- Не более пяти попыток сохранения на пользователя/базу за 15 минут; лимит хранится в БД. Сеть не удерживает транзакцию; ревизия предотвращает сохранение после параллельного отключения.
- MCP вызывается отдельной сессией с личной Basic-авторизацией. Автоматического перехода на общий технический аккаунт нет. Адрес разрешён серверным каталогом; redirects запрещены. Внутренний HTTP до `.54` идёт через VPN. Публичный HTTP с паролями запрещён.
- Модель получает только доступные названия баз и результаты чтения. Пароли, логины, SSH и адреса подключения не включаются в контекст. Результат чтения может содержать бизнес-данные: ответ с ними виден участникам обращения. Отзыв доступа останавливает последующие передачи провайдеру и публикацию результата; уже переданные данные отозвать невозможно.

## MCP и OpenAI

Разрешены только `list_metadata_objects`, `get_metadata_structure`, `get_access_rights`, `get_object`, `execute_query`. Запросы ограничены чтением, одним выражением и максимум 100 строками; метаданные — 50 объектами. Произвольный код, запись/проведение документов, удаление и привилегированный режим отсутствуют в инструментах модели. Тайм-аут MCP — 20 секунд, ограничены размеры запроса и ответа. Каждый результат привязан к ревизии подключения; доступ повторно проверяется перед очередным запросом модели и транзакционным сохранением ответа.

Responses API: последовательные вызовы функций, максимум четыре вызова инструментов на ответ, `store:false`. Тесты используют подменённый провайдер. **OpenAI API key/model ещё не настроены; на dev остаётся `HELP_AI_PROVIDER=knowledge`. Реальное автоматическое обращение модели к 1С и весь чат-сценарий с реальным OpenAI следует включить и проверить после получения ключа.** Форма и проверка подключения работают независимо от провайдера.

## Конфигурация

```dotenv
ONEC_PERSONAL_ENABLED=true
ONEC_PERSONAL_BASES_FILE=/run/secrets/onec-bases.json
ONEC_PERSONAL_KEYRING_FILE=/run/secrets/onec-keyring.json
ONEC_TRUSTED_PROXY_IPS=172.20.0.1,172.18.0.1
```

Пример файла баз (не секрет):

```json
[{"key":"torg2026","label":"Торговля · рабочая база","rpcUrl":"http://192.168.30.54/torg2026/hs/mcp/rpc","legacyGuidBinding":true,"allowVpnHttp":true}]
```

`legacyGuidBinding` можно включить только для одной базы: существующий GUID относится к конкретной информационной базе. Для добавления других баз нужны отдельные записи подключения; нельзя переносить GUID/пароль между базами. Настройки `ONEC_LP_APP_*` остаются прежними и не служат fallback.

Keyring имеет формат `{"active":"key-id","keys":{"key-id":"<32 random bytes in base64>"}}`. Для ротации добавить новый ключ и назначить active, сохранив старые ключи до перешифрования всех записей. Не удалять старые ключи без завершения перешифрования и проверки резервных копий. Автоматическая массовая ротация пока не реализована.

API: `GET /users/me/onec-connections`, `PUT /users/me/onec-connections/:baseKey` (`login?`, `password`), `DELETE /users/me/onec-connections/:baseKey`. DTO: `baseKey`, `label`, `displayName`, `login`, `loginLocked`, `mapped`, `connected`, `verifiedAt`. Имя не принимается от клиента как доверенное значение.

## Обновление каталога

Администратор экспортирует только `{guid, ibGuid, login, displayName}` из соответствующей базы, хранит временный JSON приватно и запускает в окружении API:

```sh
node dist/tools/importOnecDirectory.js torg2026 /private/onec-directory.json
```

Импортер зашифровывает значения и обновляет существующих сопоставленных пользователей. Изменение логина отзывает пароль; изменение только отображаемого имени не разрывает подключение. Временный JSON удалить после успешного импорта. Не предоставлять административный экспорт как инструмент ИИ. На текущем этапе экспорт был выполнен отдельно в режиме rollback, без изменения бизнес-данных.

## Целевые проверки

- Unit: шифрование и подмена AAD, URL/allowlist, лимиты, отсутствие секретов в ответах/ошибках, изоляция JWT, прерывание OpenAI-цикла ради формы подключения, отзыв перед передачей результатов.
- Изолированный PostgreSQL: два пользователя, отдельные реквизиты, имя отдельно от логина, отключение во время сохранения, смена GUID, блокировка, лимиты. Временная база удаляется после проверки.
- Playwright: реальный компонент формы, автоматический и ручной логин, очистка пароля, отключение, отдельное имя. Это веб-проверка формы; APK в этом этапе не собирался.
- На VDS проверена реальная цепочка HTTPS API → проверка 1С → шифрованное хранение → разрешённое чтение MCP → отзыв доступа. Использовалась временная идентичность приложения с диагностическими реквизитами; после проверки она удалена. Чтение под правами конкретного сотрудника требует ввода его собственного пароля. Проверено заполнение обоих полей у 31/31 сопоставленных пользователей. Отсутствие OpenAI-ключа отдельно ограничивает проверку полного сценария с моделью.
