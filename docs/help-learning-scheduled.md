# Периодический разбор «Помощи»

Реализован отдельный фоновый анализ качества dev-обращений. Модель по решению
владельца — **gpt-6.1-sol, reasoning high**. Astra не включена. Это накопление
проверяемого опыта вокруг модели; веса модели не переобучаются.

## Что делает запуск

1. Получает ограниченную проекцию dev-обращений через отдельный SSH-ключ с forced
   command и роль PostgreSQL `leader_help_learning_ro`. Роль читает только четыре
   view в схеме `help_learning`; прямого доступа к User, сообщениям, job context,
   учётным данным 1С, KnowledgeVersion и вложениям у неё нет.
2. Читает непрерывный префикс глобального журнала HelpEvent, максимум 20 разных
   обращений на страницу и 1000 событий. До десяти страниц, не требующих нового
   анализа, пропускаются за запуск; новые версии анализируются одной пачкой до 20.
3. Перед моделью подавляет сообщения с признаками учётных данных, убирает адреса
   и контакты, ограничивает историю/размер. Очистка эвристическая: это не обещание
   полной анонимизации любых имён и коммерческих сведений. Все результаты приватны.
4. Запускает `codex exec` с явно заданными Sol/high, чистой конфигурацией и без
   shell, Code Mode host, MCP/apps, web, hooks и субагентов. Данные диалогов не
   попадают координатору T3 и не могут стать командами. Результат — строгий JSON.
5. Проверяет точное соответствие обращениям, версиям и message IDs, очистку
   результата, а затем заново получает версии источника. Только после проверки
   атомарно сохраняет разборы и продвигает cursor.

Одна пачка имеет lease 15 минут, вызов модели ограничен 12 минутами, input/output
ограничены. Одновременная пачка только одна. Неудача/падение не подтверждает cursor;
изменившиеся источники остаются на повтор. Старые результаты помечаются STALE либо
REJECTED при отзыве доступа. Переписка, статусы прочтения, уведомления и очередь
ответов API не меняются. Параллельные ответы существующего Help worker сохранены.

## Какие результаты сохраняются

- `no_change`: нового действия не требуется.
- `needs_review`: замечания и проверочные диалоги для специалиста.
- `create`: черновик повторяемой инструкции только для полного CLOSED-обращения
  с явным положительным подтверждением OWNER/IT. Закрытие, рейтинг и уверенность
  модели не считаются доказательством. Вопросы, цитаты и поздние отрицания исключены.
- `update/rewrite` зарезервированы контрактом, но сейчас переводятся в needs_review:
  каталог и права опубликованных статей не передаются этому анализатору, поэтому
  указанный моделью documentId не считается проверенной целью изменения.

Черновики имеют только `IT_REVIEW_ONLY`/`REVIEW_REQUIRED`. Одинаковая нормализованная
инструкция не размножается; источники сохраняются отдельно. Семантические дубли
и соответствие существующим статьям проверяет редактор. Автопубликации нет.
Редактор проверяет исходное обращение, доказательства, применимость, актуальность
и аудиторию, затем использует существующий процесс Nextcloud/публикации знаний.
Динамические остатки/последние документы 1С не становятся постоянными фактами.
Анализатор не подключается к 1С и не получает личные логины/пароли сотрудников.

## Runtime

- Исходники: `scripts/help-learning/{source,privacy,contract,store,runner}.cjs`.
- Частный конфиг: workspace `.dev-runtime/help-learning/config.private.json`.
- Состояние: `.dev-runtime/help-learning/state/help-learning.sqlite`, WAL, FULL,
  права каталога 700, файлов 600. Не удалять cursor, batches и SQLite при обновлении.
- Очередь для ответственного IT/владельца:
  `.dev-runtime/help-learning/state/review-queue/journal.json` и `README.md`.
- Служебные счётчики: `node scripts/help-learning/runner.cjs status --config <private-config>`.
- Один запуск: `node scripts/help-learning/runner.cjs run --config <private-config>`.
- Восстановить файлы очереди: команда `export` с тем же конфигом.

Нужны Node.js 24, установленный Codex CLI и действующая авторизация Codex. Модель
использует существующую авторизацию Codex, ключ OpenAI API не копируется. В CLI
заданы `--ignore-user-config --ephemeral`; только ожидаемая служебная диагностика
отключённого Code Mode до начала inference допускается. Любая попытка инструмента
или ошибка во время inference отклоняет результат. Raw provider stderr/тексты
диалогов в scheduled logs не сохраняются; ошибки имеют фиксированные коды.

Источник на host126: `/opt/leader-help-learning-dev/`; env с новым паролем роли
читает только root-owned wrapper. One-off source контейнер работает read-only,
без host/secret mounts, Docker socket и опубликованных портов, с cap-drop ALL,
no-new-privileges, 256 МиБ / 0.25 CPU и отключённым Docker log driver. Его immutable
образ собран отдельным слоем над текущим API, но не заменяет API/worker.

Ключ `leader-help-learning-source-ed25519` позволяет только forced command
`help-learning-source-v1`, не обычный SSH или port-forwarding. Привилегированный
launcher не принимает произвольные аргументы; stdin проходит строгую проверку.

## Установка и сопровождение

`deploy/help-learning/prepare-source-image.py` готовит отдельный build context.
После `docker build` на126 владелец запускает `install-source.py` там с root:
он проверяет dev DB, устанавливает только views/reader-role, создаёт приватный
пароль/env, принудительную SSH-команду и узкий sudoers. Секреты в Git не попадают.
При обновлении privacy/source пересобрать immutable source image и обновить его
binding. API, Metro, T3 и глобальную маршрутизацию перезапускать не требуется.

Расписание T3 должно принадлежать **зарегистрированному проекту LeaderProductAPI**:
общая папка LeaderProduct содержит два репозитория и не подходит для автоматического
worktree provisioning. Каждый запуск координатора только вызывает runner и
возвращает счётчики; не читает полную переписку, не исправляет код и не публикует
материалы самостоятельно. При недоступности сервера/авторизации очередной запуск
завершается ошибкой, cursor сохраняется; следующий час повторяет работу.

## Проверки

`node --test scripts/help-learning/test_*.cjs` — контракты, privacy, истинность
подтверждения, межпроцессная гонка, crash recovery, backlog, source revocation,
ограничение вывода/таймаута процесса и запрет инструментов. PG-тест отдельно
работает только на синтетическом PostgreSQL16 с фиксированным localhost.
`HELP_LEARNING_SYNTHETIC=1` включать исключительно в этом изолированном стенде.
Новый CI workflow создаёт свой PostgreSQL16; работающие базы не используются.

Тексты вложений и полные tool traces отсутствуют: анализатор не должен объявлять
инструмент неиспользованным только по отсутствию его трассы в снимке. Для сравнения
нового prompt/model на старых данных используйте отдельное состояние анализа,
сохраняя прежний SQLite и происхождение результатов; не сбрасывайте текущий cursor.
