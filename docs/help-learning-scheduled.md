# Периодический разбор «Помощи»

Реализован отдельный фоновый анализ качества dev-обращений. Модель по решению
владельца — **gpt-6.1-sol, reasoning high**. Astra не включена. Это накопление
проверяемого опыта вокруг модели; веса модели не переобучаются.

## Что делает запуск

1. Получает ограниченную проекцию dev-обращений через отдельный SSH-ключ с forced
   command и роль PostgreSQL `leader_help_learning_ro`. Роль читает только четыре
   view в схеме `help_learning`; прямого доступа к User, сообщениям, job context,
   учётным данным 1С, KnowledgeVersion и вложениям у неё нет.
2. Читает непрерывный префикс глобального журнала HelpEvent, максимум 20 разных
   обращений на страницу и 1000 событий. До десяти страниц, не требующих нового
   анализа, пропускаются за запуск; новые версии анализируются одной пачкой до 20.
3. Перед моделью подавляет сообщения с признаками учётных данных, убирает адреса
   и контакты, ограничивает историю/размер. Очистка эвристическая: это не обещание
   полной анонимизации любых имён и коммерческих сведений. Все результаты приватны.
4. Запускает `codex exec` с явно заданными Sol/high, чистой конфигурацией и без
   shell, Code Mode host, MCP/apps, web, hooks и субагентов. Данные диалогов не
   попадают координатору T3 и не могут стать командами. Результат — строгий JSON.
5. Проверяет точное соответствие обращениям, версиям и message IDs, очистку
   результата, а затем заново получает версии источника. Только после проверки
   атомарно сохраняет разборы и продвигает cursor.

Одна пачка имеет lease 20 минут, вызов модели ограничен 12 минутами, input/output
ограничены. Одновременная пачка только одна. Неудача/падение не подтверждает cursor;
изменившиеся источники остаются на повтор. Старые результаты помечаются STALE либо
REJECTED при отзыве доступа. Переписка, статусы прочтения, уведомления и очередь
ответов API не меняются. Параллельные ответы существующего Help worker сохранены.

## Какие результаты сохраняются

- `no_change`: нового действия не требуется.
- `needs_review`: замечания и проверочные диалоги для специалиста.
- `create`: черновик повторяемой инструкции только для полного CLOSED-обращения
  с явным положительным подтверждением OWNER/IT. Закрытие, рейтинг и уверенность
  модели не считаются доказательством. Вопросы, цитаты и поздние отрицания исключены.
- `update/rewrite` зарезервированы контрактом, но сейчас переводятся в needs_review:
  каталог и права опубликованных статей не передаются этому анализатору, поэтому
  указанный моделью documentId не считается проверенной целью изменения.

Черновики имеют только `IT_REVIEW_ONLY`/`REVIEW_REQUIRED`. Одинаковая нормализованная
инструкция не размножается; источники сохраняются отдельно. Семантические дубли
и соответствие существующим статьям проверяет редактор. Автопубликации нет.
Редактор проверяет исходное обращение, доказательства, применимость, актуальность
и аудиторию, затем использует существующий процесс Nextcloud/публикации знаний.
Динамические остатки/последние документы 1С не становятся постоянными фактами.
Анализатор не подключается к 1С и не получает личные логины/пароли сотрудников.

## Runtime

- Исходники: `scripts/help-learning/{source,privacy,contract,store,runner}.cjs`.
- Частный конфиг: workspace `.dev-runtime/help-learning/config.private.json`.
- Состояние: `.dev-runtime/help-learning/state/help-learning.sqlite`, WAL, FULL,
  права каталога 700, файлов 600. Не удалять cursor, batches и SQLite при обновлении.
- Очередь для ответственного IT/владельца:
  `.dev-runtime/help-learning/state/review-queue/journal.json` и `README.md`.
- Служебные счётчики: `node scripts/help-learning/runner.cjs status --config <private-config>`.
- Один запуск: `node scripts/help-learning/runner.cjs run --config <private-config>`.
- Восстановить файлы очереди: команда `export` с тем же конфигом.

Нужны Node.js 24, установленный Codex CLI и действующая авторизация Codex. Модель
использует существующую авторизацию Codex, ключ OpenAI API не копируется. В CLI
заданы `--ignore-user-config --ephemeral`; только ожидаемая служебная диагностика
отключённого Code Mode до начала inference допускается. Любая попытка инструмента
или ошибка во время inference отклоняет результат. Raw provider stderr/тексты
диалогов в scheduled logs не сохраняются; ошибки имеют фиксированные коды.

Источник на host126: `/opt/leader-help-learning-dev/`; env с новым паролем роли
читает только root-owned wrapper. One-off source контейнер работает read-only,
без host/secret mounts, Docker socket и опубликованных портов, с cap-drop ALL,
no-new-privileges, 256 МиБ / 0.25 CPU и отключённым Docker log driver. Его immutable
образ собран отдельным слоем над текущим API, но не заменяет API/worker.

Ключ `leader-help-learning-source-ed25519` позволяет только forced command
`help-learning-source-v1`, не обычный SSH или port-forwarding. Привилегированный
launcher не принимает произвольные аргументы; stdin проходит строгую проверку.

## Установка и сопровождение

`deploy/help-learning/prepare-source-image.py` готовит отдельный build context.
После `docker build` на126 владелец запускает `install-source.py` там с root:
он проверяет dev DB, устанавливает только views/reader-role, создаёт приватный
пароль/env, принудительную SSH-команду и узкий sudoers. Секреты в Git не попадают.
При обновлении privacy/source пересобрать immutable source image и обновить его
binding. API, Metro, T3 и глобальную маршрутизацию перезапускать не требуется.

Расписание T3 должно принадлежать **зарегистрированному проекту LeaderProductAPI**:
общая папка LeaderProduct содержит два репозитория и не подходит для автоматического
worktree provisioning. Каждый запуск координатора только вызывает runner и
возвращает счётчики; не читает полную переписку, не исправляет код и не публикует
материалы самостоятельно. При недоступности сервера/авторизации очередной запуск
завершается ошибкой, cursor сохраняется; следующий час повторяет работу.

## Разбор замечаний и проверка исправлений — следующий этап

К SQLite добавлены отдельные сущности замечаний, источников, наблюдений и переходов.
Существующие cursor, reviews, drafts и lease не сбрасываются; прежние замечания
переносятся идемпотентно. Идентичность замечания: обращение + код + message IDs.

Статусы: `NEW → CONFIRMED → FIXED → VERIFIED`; `DISMISSED` с причинами historical,
already_fixed или insufficient_snapshot. Отзыв/изменение источника хранится отдельно
как REVOKED/STALE, не выдаётся за исправление. Модель создаёт только наблюдения;
переходы делает доверенный оператор с ожидаемым текущим статусом и доказательствами.
FIXED требует успешного теста и dev-развёртывания; VERIFIED — нового успешного теста
после FIXED. Регрессия переоткрывается только свежим отрицательным доказательством.
Переходы и их SHA-256 остаются в append-only журнале, старые результаты не стираются.

Приватная очередь: `state/issue-queue/journal.json`; CLI `triage.cjs`:

```sh
node scripts/help-learning/triage.cjs list --state-dir <private-state> --limit 1000
node scripts/help-learning/triage.cjs transitions --state-dir <private-state> --issue <issue-id>
node scripts/help-learning/triage.cjs transition --state-dir <private-state> \
  --issue <issue-id> --expect NEW --to CONFIRMED --operator workspace-owner \
  --rationale '<проверенное объяснение>' --evidence <private-manifest.json>
```

Manifest: `{schemaVersion:1,evidence:[{kind,ref,sha256,outcome,observedAt,artifact}]}`.
kind: inspection/test/deployment; outcome: PASS/FAIL/CONFIRMED; observedAt: epoch ms.
artifact — имя соседнего файла, без путей/симлинков, до 2 MiB; CLI сверяет его хеш.
ref — короткий идентификатор проверки, без URL, команд и секретов. Для DISMISSED
нужен также `--reason historical|already_fixed|insufficient_snapshot`.

Первоначально источник был расширен только минимальными метаданными файлов и публичных действий:
kind/extension/size/mimeType, allowlisted toolName/status/errorCode и факт подготовки
изображения. Имена, object keys, URL, содержимое файлов, raw assistantState и аргументы
инструментов не выдаются. Отсутствие legacy metadata означает UNKNOWN, не «нет файла».
Привязанный файл не доказывает успешное скачивание; подготовка изображения не
позволяет оценить точность распознавания без изображения. Обрезка списков явная;
размеры JSON учитывают экранирование и метаданные, большие обращения не голодают.
Аддитивное обновление view сохраняет существующие зависимости и SELECT-only роль.

Root-owned `source-launcher.py` добавляет только публичные возможности текущего
образа: digest, модель/reasoning/provider, проверенные TXT/MD/CSV/JSON. Это описание
текущего сервера, не доказательство возможностей исторического ответа. Подготовка
образа копирует launcher; `install-source.py --input-root <scoped-bundle>` позволяет
установить его без восстановления глобальных runtime bind mounts. API не перезапускается.

Prompt v2 получает известные замечания текущих обращений и их статусы, не повторяет их по старым
сообщениям и явно учитывает ограничения снимка. Часовая задача остаётся в прежнем
постоянном чате, модель Sol/high; ни переходы статусов, ни исправление кода, ни
публикация знаний по тексту обращения ей не разрешены.

В dev API/worker установлен `leaderproductapi:help-review-fixes-dev-20261105-r1`,
точечный слой поверх `help-agent-context-dev-20261105-r3`. Сохранены личная 1С,
публичная активность, ACL/lease fences и OTA asset filenames. Текущая модель Help
при выпуске — gpt-6.1-sol/medium; модель анализатора отдельно Sol/high.

Исправления: локальный guard ответов/потока/вопросов/файлов блокирует опасные советы
отключать защиту, запускать с повышенными правами и менять конфигурацию 1С; отдельное
приветствие не вызывает сетевой шаблон. Лексическая проверка не является полной
модерацией или системой авторизации. При предложении IT сохраняется причина сбоя;
фразы о якобы завершённой передаче убираются, требуется кнопка и подтверждение.
Патчер `patch-answer-runtime.cjs` сохраняет остальной активный код и отказывает при
неизвестной форме. Полные грязные Help-исходники нельзя заменять старым branch build.

Проверено: 1213 API-тестов, TypeScript, семь регрессий на работающем образе и два
настоящих вызова Sol без записей обращений/уведомлений и без запросов к 1С.
Первичный triage 26 замечаний: 2 VERIFIED, 15 DISMISSED, 9 NEW для дополнительной
проверки. DISMISSED включает старый симулятор/T3 и выводы без требуемых данных;
он не означает, что старый ответ правильный. Среди NEW остаются объяснения прав
и ошибок 1С, релевантность источников, повторы уточнений и старый файловый ответ.


Первый end-to-end запуск v2 повторно разобрал 20 изменившихся снимков, без stale
результатов, и сохранил cursor 1010. Исправленные/снятые замечания не открылись.

## Полнота данных анализатора — projection/prompt v3

Исправлен воспроизводимый дефект: очистка адресов удлиняла старые сообщения,
после чего повторный лимит в хронологическом порядке обнулял последний ответ.
Теперь все текстовые бюджеты расходуются от новых сообщений к старым после
очистки. `textComplete` имеет true/false/null: оригинал целиком, изменённый либо
обрезанный текст, неизвестная полнота старого снимка. JSON-ограничение также
помечает конкретный изменённый текст. Признак сохраняется при повторной sanitation.

`projectionVersion=3` входит в sourceVersion; обновление проекции создаёт новые
снимки, не требует удаления SQLite/cursor и сохраняет прежние разборы как историю.
Доверенная роль ASSISTANT получается через HelpAssistantJob.messageId/ticketId/
ownerId и null authorId, а не по одному текстовому authorRole SYSTEM/ASSISTANT.

Добавлены только минимальные сведения о вопросах: известность метаданных,
несколько пар multiSelect/optionCount, признак усечения и статус задания.
Тексты вопросов/ответов, labels, IDs, личные черновики и raw assistantState не
выдаются. XLSX/DOCX расширения/MIME и названия двух офисных инструментов входят
в whitelist. Привязка файла не доказывает качество таблицы/формулы или скачивание.

Root launcher проверяет текущие Office-возможности двумя фиксированными малыми
синтетическими генерациями в памяти. Нет БД, модели, 1С, storage и записи файлов;
наружу уходят только разрешённые расширения. Сбой пробы означает UNKNOWN, а не
«Office не поддерживается». Это текущие возможности, не история прошлых образов.

Prompt v3 учитывает эти признаки. Контракт отклоняет EMPTY_RESPONSE без полного
пустого текста завершённого серверного ответа, известных полных метаданных и
подтверждённого отсутствия файлов/вопросов. Модель не меняет triage-статусы.
Прежние ложные EMPTY_RESPONSE по37/40 переведены оператором из NEW в DISMISSED
с хешами проверок; история и исходные наблюдения сохранены. Источник v3 развёрнут
отдельно от API/worker, без их перезапуска. Реальный Sol/high повторно разобрал
восемь обращений37–44:8 REVIEWED,0 stale,0 новых записей замечаний,0 инструкций;
cursor1478 сохранён. По37/40 повторный разбор не нашёл EMPTY_RESPONSE.

Четыре ранее известных наблюдения по38/41/42/43 остались NEW, а не подтверждёнными
дефектами. В частности, текущие Office-возможности не доказывают возможности
прошлого образа, а наличие вопросов в серверном снимке не доказывает поведение
интерфейса устройства. Глобально после проверки:20 NEW,17 DISMISSED,2 VERIFIED.
CI42000932685 прошёл77 Node-тестов с PostgreSQL16,5 Python-тестов и105 policy
тестов. Расписание остаётся каждые4 часа на Sol/high в прежнем постоянном чате.

## Содержимое файлов и результаты 1С — проекция v4, 2026-11-06

Фиксированный root-owned launcher сначала получает прежнюю SELECT-only проекцию,
затем запускает доверенный `evidence-reader.cjs` внутри существующего dev API.
Его вход — только выбранные ticketId/messageId, без SQL, путей, URL или object keys.
Коллектор проверяет dev DB, открывает READ ONLY транзакцию и повторяет eligibility
через `help_learning.tickets_v1`. Он читает только привязанные к выбранным сообщениям
вложения и private `HelpAssistantJob.context.helpAnalysisEvidence`. Модель и T3
координатор не получают доступ к API/S3/SSH, полномочиям или учётным данным.
Это расширение доверенного источника, а не расширение инструментов inference.

Новые вызовы чтения 1С сохраняются после каждого результата/кода ошибки отдельным
fenced sink: live lease, текущий владелец/обращение, source/history/app ACL и
персональные 1С proofs проверяются перед записью. В private envelope сохраняются
аргументы и фактическое тело ответа, status, rowCount, sourceTruncated и полнота.
Секретные ключи/URL подавляются до записи; исключение передаёт только безопасный
код. Предел одной последней попытки: 12 вызовов / 512 KiB; превышение явно отмечено.
Этот envelope не попадает в assistantState, сообщения, события, уведомления или
публичный progress. Предыдущие попытки не смешиваются с proofs текущей попытки.
Исторические тела 1С, которые не сохранялись, восстановить таким способом нельзя.

Для вложений сначала сверяются размер и SHA-256 с привязанной записью. XLSX/CSV
передают листы, предполагаемые заголовки, типы, реальные количества строк/колонок,
образец строк и признаки полноты. TXT/MD/JSON/DOCX/PDF передают извлечённый текст.
Формулы и макросы не выполняются; скан PDF без текста требует OCR, изображения
не анализируются. Парсер запускается отдельным процессом с очищенным окружением,
heap 192 MiB, таймаутом 10 s, ограничениями ZIP/XML/размера/ячеек/вывода. API
контейнер сохраняет свои существующие cgroup limits. Один файл до 10 MiB,
до 6 разобранных файлов на обращение, до 16 метаданных файлов; лимиты детерминированы
на обращение, чтобы состав пачки не менял sourceVersion.

Перед inference privacy повторно очищает содержимое/колонки/args/results и
ограничивает evidence 64k байт UTF-8, весь snapshot 180k байт, модельную пачку 200k символов.
Большие результаты могут быть частичными — полнота каждого тела и исходной выборки
отмечается отдельно. Отсутствие сохранённого тела, unsupported/failed файл и
усечение не превращаются в успешное чтение или доказательство пустого результата.
Версия источника v4 включает digest прежней проекции и очищенное evidence; свежая
проверка перед сохранением повторяет чтение. Изменение/отзыв источника делает разбор
устаревшим. Все тексты/ячейки/запросы остаются недоверенными данными.

Prompt v4 сравнивает запрос пользователя, вывод помощника, фактическую структуру
файла и доступные аргументы/результаты запросов. Описательный лист может не выполнять
заказанную выгрузку; настоящий пустой табличный результат с нужными заголовками
допустим. Проверяется соответствие периода, фильтров, полей, типов и сделанных выводов.
Результаты остаются IT_REVIEW_ONLY/REVIEW_REQUIRED, автоматического исправления,
смены статусов замечаний и публикации знаний нет.

## Сопровождение исправлений без второго набора статусов

`issue-queue/followup.json` дополняет существующий журнал замечаний. Он автоматически
обновляется при обычном `writeJournal` и показывает следующий требуемый шаг:
классификация причины, воспроизведение на текущем runtime, регрессионный тест,
проверка развёртывания или запрос доверенного перехода FIXED/VERIFIED. Сами статусы
остаются в прежних `issues`/`issue_transitions`; отчёт не меняет SQLite, cursor,
lease, решения оператора, расписание и модель и ничего не публикует в знания.

Категории: AI_BEHAVIOR, INTEGRATION, HUMAN_COMMUNICATION, SYSTEM_LIFECYCLE, UNKNOWN.
Код замечания даёт только `suggestedCategory`. Доверенная `category` появляется
из приватного плана оператора; неподтверждённое назначение остаётся UNKNOWN.
Сервисные замечания к общению IT направляются на HUMAN_SERVICE_REVIEW, а не на
автоматическое изменение модели, переписки или кадровые выводы. Устаревший/отозванный
источник требует повторной проверки и не считается автоматически исправленным.

План `<stateDir>/issue-queue/followup-plan.json` имеет вид:

```json
{
  "schemaVersion": 1,
  "audience": "IT_REVIEW_ONLY",
  "operator": "workspace-owner",
  "entries": [{
    "issueId": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "category": "AI_BEHAVIOR",
    "testCases": ["help.handoff-single-instruction"],
    "evidenceManifest": "handoff-evidence.json"
  }]
}
```

План и соседние manifest/artifact-файлы подготавливает доверенный оператор.
`evidenceManifest` использует уже существующий формат доказательств `triage.cjs`;
SHA-256 сверяется с фактическими байтами соседних файлов. Test `ref` должен совпадать
с зарегистрированным `testCases` ID: чужой успешный тест не подтверждает этот случай.
Пример не является выполненным тестом; его нельзя подменять словом PASS или
заключением модели. inspection/PASS подтверждает успешное чтение или проверку
источника; для подтверждения дефекта требуется отдельное inspection/CONFIRMED
либо связанный FAIL регрессии на текущем коде. Отчёт показывает необходимость отдельного перехода через
`triage.cjs`, а не выполняет его. Проверка VERIFIED требует нового успешного
связанного теста после FIXED и после развёртывания; регрессия закрытого замечания —
свежего связанного FAIL. Историческое время возникновения и актуальность снимка
сами по себе не подтверждают воспроизводимость на действующем коде.

Повреждённый, слишком большой, публично читаемый или ссылочный план и неверный
хеш артефакта получают `planState=INVALID`; наблюдения остаются UNKNOWN. Ошибка
необязательного плана не должна превращать успешный разбор обращений в неуспешный.
Вывод не содержит описаний замечаний, переписки, результатов инструментов или
содержимого доказательств: только ID, категории, ссылки/хеши, статусы и счётчики.

Отдельный безопасный отчёт без inference и без открытия записывающего store:

```sh
node scripts/help-learning/followup.cjs report --state-dir <private-state>
```

SQLite открывается readOnly, вывод пишется только в фиксированный приватный
`issue-queue/followup.json` атомарной заменой; stdout содержит только счётчики.
Команда не запускает тесты/код из модели, не обращается к источнику или OpenAI,
не меняет статусы и не повторяет бизнес-операции. Реальные синтетические регрессии
запускаются штатными проверенными тестовыми командами разработчика; их результаты
проверяет оператор и привязывает к case ID существующим manifest-протоколом.


Богатая store-пачка до 20 обращений анализируется последовательно частями до 5.
Общий модельный deadline всей пачки остаётся 12 минут, суммарный event budget —
4 MiB. Каждая часть валидируется по своим sourceVersion/message IDs, затем
объединённый результат — по всей пачке. Ошибка части, времени, протокола или вывода
не даёт частичной записи. Перед единым commit повторно читаются все источники.
Это не несколько независимых cursor; lease общей пачки — 20 минут. DOCX/PDF
передают только извлечённый текст; полнота текста не доказывает чтение изображений.

Реальный штатный прогон v4 после этой доработки завершён: 20 reviewed, 0 stale,
4 последовательные части, строгий протокол без ошибок во время inference.
Cursor3505 сохранён (новых событий в scan не было); исторические reviews и issue
statuses сохранены. Две предыдущие крупные попытки завершились fail-closed и не
засчитываются как успешные. Ожидаемая диагностика disabled Code Mode до inference
по-прежнему допустима; остальные ошибки не игнорируются.
