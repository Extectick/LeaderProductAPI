# Адаптер OpenAI и проверка качества поиска

Дата: 1 ноября 2026. Реализован серверный адаптер; ключ и модель не настроены, внешние вызовы выключены. Код развёрнут на dev вместе с [персональным подключением 1С](onec-personal-connections.md), провайдер dev остаётся `knowledge`. Production не изменялся.

## Что готово

- Responses API через встроенный HTTP-клиент Node; новых зависимостей нет. Фиксированный `https://api.openai.com/v1/responses`, редиректы запрещены.
- Строгая JSON-схема решения: ответ, уточняющий вопрос или передача в IT. Сервер дополнительно проверяет структуру, размер текста и идентификаторы источников. Названия, версии и пути источников добавляет сервер, а не модель.
- Контекст включает первое сообщение пользователя и недавнюю переписку: до 16 сообщений и 6 000 символов; до трёх документов и 9 500 символов выдержек. Файлы целиком, вложения, профили пользователей и подписанные URL не загружаются.
- Документы, сообщения и результаты инструментов передаются как недоверенные данные. При настроенном `ONEC_PERSONAL_ENABLED` доступны ограниченные инструменты чтения 1С с личными правами сотрудника; команды, запись, веб-поиск и загрузка файлов не предоставляются. Это уменьшает возможности внедрённых инструкций, но не заменяет проверку качества ответов реальной модели.
- `store:false`, собственная история в PostgreSQL; удалённая цепочка `previous_response_id` не используется. Это отключает хранение Responses для последующего получения, **но не является обещанием Zero Data Retention**: условия обработки данных аккаунта нужно проверить до включения.
- Проверка актуальности и доступности источников до передачи провайдеру и перед сохранением ответа. При отзыве/изменении во время запроса результат не сохраняется, задание готовит ответ заново. Уже отправленные провайдеру данные нельзя отозвать задним числом.
- Без документов и без настроенных инструментов 1С обращение передаётся в IT без платного запроса. С включёнными инструментами модель может проверить 1С; отсутствие личного доступа возвращает кнопку подключения. Отказ модели и решение `handoff` ведут в IT. `clarify` сохраняется как вопрос в текущем чате.
- В успешном ответе сохраняются модель, ID ответа и usage. Socket-событие и запись в outbox создаются той же транзакцией, что финальное сообщение.

## Выключение и будущее включение

Сейчас настройки должны оставаться такими:

```dotenv
HELP_AI_PROVIDER=knowledge
HELP_OPENAI_ENABLED=false
HELP_OPENAI_MODEL=
OPENAI_API_KEY=
OPENAI_API_KEY_FILE=
```

После получения ключа выбрать модель с поддержкой Responses и Structured Outputs, проверить правила обработки корпоративных данных и лимиты расходов. Включение требует **всех** параметров в окружении API и Help worker:

```dotenv
HELP_AI_ENABLED=true
HELP_AI_PROVIDER=openai
KNOWLEDGE_ENABLED=true
HELP_OPENAI_ENABLED=true
HELP_OPENAI_MODEL=<выбранная-модель>
OPENAI_API_KEY_FILE=/run/secrets/openai_api_key
HELP_OPENAI_TIMEOUT_MS=60000
HELP_OPENAI_MAX_OUTPUT_TOKENS=1500
HELP_OPENAI_MAX_ATTEMPTS=3
```

Файл ключа монтируется только серверным контейнерам, приватно и только на чтение. Альтернатива — `OPENAI_API_KEY` в приватном env-файле; `OPENAI_API_KEY_FILE` имеет приоритет. Секрет не нужен APP, его нельзя записывать в `EXPO_PUBLIC_*`, Git, логи или Markdown. Один ключ не включает провайдера. При отсутствии ключа/модели либо флагов HTTP-запрос не выполняется.

Не переключать текущий Compose overlay простым добавлением ключа: `compose.help-knowledge-dev.yml` явно закрепляет `HELP_AI_PROVIDER=knowledge`. Для активации нужен отдельный выпуск API/Help worker и override настроек. Перед ним — резервная копия и проверка только dev. До ключа развёртывание не требуется.

Для возврата к локальным выдержкам установить `HELP_AI_PROVIDER=knowledge`, `HELP_OPENAI_ENABLED=false` и применить настройки к API/worker. Уже поставленные OpenAI-задания не смогут отправить новый внешний запрос при выключенном провайдере.

## Отмена, повторы и ограничения

Запрос выполняется вне транзакции БД. Пока он идёт, worker раз в две секунды проверяет владение заданием и продлевает действующий lease на 90 секунд. Уточнение пользователя, отмена или подключение IT прерывают HTTP-запрос. Перед финальной записью сохраняется проверка токена владения: прежний исполнитель не может опубликовать ответ.

Остановка worker прерывает запрос и возвращает ещё принадлежащее ему задание в очередь. Завершение локального HTTP-запроса не гарантирует остановку вычисления у провайдера. После сбоя между получением ответа и фиксацией в БД возможен повторный платный вызов; ровно один внешний вызов не гарантируется. Финальное сообщение/событие защищены от дублей.

HTTP 408/429/5xx, сетевые сбои и таймауты повторяются через существующую очередь. Учитывается `Retry-After` до пяти минут. Ошибки конфигурации, авторизации, JSON и вымышленные ссылки не повторяются автоматически. Тело ошибки провайдера не сохраняется и не выводится в лог.

Пределы: таймаут 1–300 секунд, выход 128–4 000 токенов, 1–5 попыток. Значения по умолчанию — 60 секунд / 1 500 токенов / 3 попытки. Это ограничение отдельного задания, **не общий суточный денежный бюджет**. Учёт всех платных попыток и глобальные квоты остаются отдельным этапом перед масштабированием. Без живого ключа совместимость выбранной модели, доступность аккаунта, стоимость и качество генерации не проверены.

## Проверки без ключа

```bash
npm run test:help-openai
npm run build
```

Unit-тесты подменяют HTTP-границу и запрещают настоящую сеть. Проверяют явное включение, контракт запроса, лимиты, JSON, ссылки, отказ/неполный ответ, ошибки, отмену, таймаут и heartbeat.

`npm run test:help-openai:flow` проверяет реальные транзакции Help и outbox с подменённым HTTP. Запускается **из корня API**, где есть `dist`, только в отдельной БД `LeaderAPI_help_openai_test` с `KNOWLEDGE_EVAL_CONFIRM=isolated`. Перед запуском нужна пустая копия схемы API, включая миграцию/FTS-триггер знаний; не копия пользовательских данных.

Рабочие dev/prod БД этот тест не принимает. API, push-доставщик и обычные worker-процессы в тестовой среде не запускаются. Синтетические пользователи/обращения существуют только в удаляемой тестовой БД.

01.11.2026 прошли TypeScript-сборка, 40 целевых unit-тестов и интеграционный сценарий на PostgreSQL 16: сохранение ответа/источников/usage, одно финальное событие и outbox, отсутствие внешнего запроса без знания/ключа, Retry-After, предел попыток, отклонение вымышленных ссылок, уточнение и передача в IT, прерывание при новом сообщении, возобновление после остановки worker и повторная проверка всех источников. Тестовые БД удалены; работающие контейнеры не пересоздавались. Вызовы OpenAI полностью подменены; реальная модель и push на устройстве этим не проверены.

## Качество поиска

Отдельные файлы корпуса и вопросов находятся в `__tests__/fixtures/knowledge-quality.*.json`. Набор содержит 14 синтетических документов и 32 вопроса: точные формулировки, словоформы/перефразировки, неизвестные ошибки, посторонние темы и недоступные версии. Корпус не является реальными инструкциями компании.

Runner использует настоящий PostgreSQL FTS и тот же `searchHelpKnowledge`, что worker. Новая фильтрация требует совпадения не менее 60% значимых терминов; явно указанные буквенно-цифровые/числовые коды должны присутствовать. Новый код в последнем уточнении заменяет старые коды при поиске. Это консервативный лексический фильтр, а не семантическая уверенность; синонимы и произвольные перефразировки пока не гарантируются.

Для запуска подготовить **пустую** БД `LeaderAPI_help_openai_test` с копией схемы, включая FTS-триггеры, собрать `dist` и передать окружение:

```dotenv
DATABASE_URL=<URL отдельной LeaderAPI_help_openai_test>
NODE_ENV=test
REDIS_DISABLE=1
KNOWLEDGE_EVAL_CONFIRM=isolated
KNOWLEDGE_ENABLED=true
KNOWLEDGE_SOURCE_KEY=search-quality-isolated
KNOWLEDGE_NEXTCLOUD_URL=https://knowledge.example.org
KNOWLEDGE_NEXTCLOUD_USER=reader
KNOWLEDGE_NEXTCLOUD_PASSWORD=fixture
HELP_AI_ENABLED=false
HELP_OPENAI_ENABLED=false
```

Секрет источника здесь фиктивный; WebDAV не вызывается. Переменные `*_PASSWORD_FILE` не должны указывать на реальное хранилище. Runner не загружает env-файлы сам; общий bootstrap API может их читать, поэтому параметры тестовой среды должны быть явно заданы до запуска.

```bash
npm run eval:help-search -- --report search-quality.json
```

Проверки: Recall@3 ≥ 95%, MRR ≥ 0.9, корректное отсутствие результата — 100%, утечки запрещённых документов — 0. Невыполнение порога возвращает ненулевой код. `--baseline` измеряет прежний поиск без нового фильтра и сохраняет отчёт без остановки на порогах. Каждый прогон требует новой пустой тестовой БД; существующее содержимое не очищается автоматически.

Сохранённые отчёты: [до изменения](evals/help-search-2026-11-01.baseline.json), [после изменения](evals/help-search-2026-11-01.json). Поиск нужных источников: 20/20 и до, и после; правильное отсутствие ответа: **6/12 → 12/12**. Запрещённые документы не раскрывались. Это результат малого синтетического набора, не оценка всего корпуса компании. Следующий контрольный набор нужно составить из реальных обезличенных вопросов и проверенных инструкций, отдельно от настройки фильтра.
