# Ограничение данных на устройстве — 17.09.2026

API хранит общий набор данных. Ограничения относятся к скачиванию на устройство, а не к удалению справочников API.

- [x] Уточнено: контрагенты основного менеджера / действующего договора / действующего соглашения; менеджер определяется авторизацией.
- [x] Проверен источник движения: активные записи ТоварыНаСкладах, ВНаличии <> 0, последние 3 календарных месяца, без будущих движений. Нулевой итоговый оборот не исключает товар.
- [x] 1С передаёт компактный снимок области офлайн-доступа: последние движения, связи видов цен, разрешённые организации/склады.
- [x] API фильтрует каталог, цены, остатки и резервы одинаково; хранение общих данных не меняется.
- [x] Виды цен: соглашения доступных контрагентов + транзитивные базовые/влияющие виды; защита от циклов. Цены берутся из регистров, формулы не вычисляются заново.
- [x] Изменение области/истечение трёх месяцев меняет epoch: телефон заменяет старый снимок, удаляя лишние записи. Менеджер входит в ключ версии.
- [x] Автотесты, сверка с WMS15, dev API и первая синхронизация.
- [x] Включить только исходящие задания WMS15 → dev; импорт заказов и production не затрагивать.

Нельзя считать датой движения дату выгрузки/изменения карточки. При ошибке обновления снимок на устройстве сохраняется. Старые онлайн endpoints остаются без новых ограничений.

Проверки: TypeScript, 20 unit-тестов; read-only запросы WMS15 — 2344 товара после исключений, 970 связанных видов цен и 78791 строка общих продажных цен. На телефон передаётся подмножество по менеджеру. В API найдено 1826 закрытых договоров: такие договоры больше не дают связь менеджер–контрагент.

Совместимость: до первого POST `/api/1c/offline-policy` старое расширение продолжает работать. После получения снимка фильтр применяется к SQLite-каталогу и офлайн-наборам. В PostgreSQL добавляется только таблица OfflineExportPolicy. APK/OTA для фильтра не требуются. Проверка физического устройства остаётся отдельной от проверки API.

Найдено при живой проверке: экспорт договоров не передавал purpose/validFrom/validTo; из-за этого проверка пригодности договора API делала все договоры неактивными. В расширение добавлены реальные ТипДоговора и даты. Также старый протокол stock прикрепляет общескладские остатки к технической организации. Политика передаёт этот ключ; офлайн-выборка не смешивает его со старыми остатками копии production и отдаёт общескладской остаток без ограничения на организацию документа. Личные резервы сохраняют собственную область пользователя. Дополнительный тест проверяет неизменность ключа delta при этой нормализации.
