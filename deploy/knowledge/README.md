# Файловая база знаний LeaderProduct

Это отдельный пилот Nextcloud на `155.212.144.191`, каталог `/opt/leader-knowledge`, Compose-проект `leader-knowledge`. Он не использует контейнеры, БД, Redis или бакет вложений API. Архитектура и следующие этапы: [план ИИ и базы знаний](../../docs/help-ai-knowledge-plan.md).

## Вход и файлы

- Адрес: `https://cloud.leader-product.ru`.
- Администратор: `knowledge-admin`.
- Пароль на рабочем компьютере: `LeaderProductAPI/.env.nextcloud.local`. Файл приватный и исключён из Git; его содержимое нельзя отправлять в логи или коммит.
- В Nextcloud откройте `База знаний`: `Материалы компании`, `Рабочая область ИИ`, `Архив`.
- Бакет: `66f2164cfa3e-leader-knowledge`, endpoint `https://s3.ru1.storage.beget.cloud`, region `ru1`, path-style включён.
- Это **External Storage**: имена объектов и папок остаются читаемыми. Primary Object Storage не используется.

В пилоте доступны два отдельных подключения того же бакета: `knowledge-admin` может редактировать, а неадминистративный `knowledge-indexer` — только читать. Публикация ссылок отключена. Запись индексатором проверена и возвращает HTTP 403. Папки не заменяют права и статус публикации: API имеет отдельную область пользователей/отделов и разрешение `manage_knowledge`. До подключения редакторов разных подразделений нужно согласовать их права Nextcloud с областью публикации API.

Обычные изменения файлов выполняйте через Nextcloud. Изменение объектов напрямую через S3/SFTP требует последующего обновления файлового кэша Nextcloud и не создаёт полноценную историю действий Nextcloud.

## Проводник Windows

1. Установить [официальный клиент Nextcloud](https://nextcloud.com/install/#install-clients).
2. Ввести адрес сервера, войти в браузере и разрешить клиенту доступ.
3. Рабочая папка пользователя: `V:\Leader-Product-Cloud`; база знаний находится в `V:\Leader-Product-Cloud\База знаний`.
4. Создать небольшой документ в `Материалы компании`, проверить его в веб-интерфейсе и отредактировать обратно.

31 октября 2026 пользователь установил клиент Windows и подключил `knowledge-admin` к `V:\Leader-Product-Cloud`. Все 18 согласованных папок появились в `База знаний`. Стандартные примеры Nextcloud удалены по запросу пользователя; служебные `.sync_*`, `.nextcloudsync.log` и `Desktop.ini` сохранены для работы клиента. Двустороннее редактирование проверено на отдельном контрольном документе: Windows → Nextcloud и изменение WebDAV → Windows. Для синхронизации клиент Nextcloud должен работать; при проверке он был закрыт и запущен из `V:\Nextcloud\nextcloud.exe`. Для повседневной работы позже следует использовать отдельную учётную запись редактора, а административную — только для управления.

## Файлы развёртывания

| Файл | Назначение |
|---|---|
| `compose.yml`, `.env.example` | Изолированные Nextcloud, PostgreSQL, Redis и cron; образы закреплены digest |
| `prepare.py` | Создание секретов без перезаписи существующих, приватные права |
| `configure.py` | Проверка выделенного бакета, подключение только администратору, создание отсутствующих папок |
| `prepare-indexer.py` | Отдельная учётная запись и read-only подключение индексатора; создаёт приватный `.env.knowledge.worker` |
| `compose.worker-dev.yml` | Ограниченный worker индексации в сети dev API; отдельный от Nextcloud |
| `folders.json` | Структура каталогов, без пользовательского содержимого |
| `nginx.conf.example` | HTTPS reverse proxy на loopback `127.0.0.1:18120` |
| `acme-dns-hook.py` | Ожидание TXT-проверки сертификата, до 30 минут |
| `backup.py` | Согласованная копия служебной БД, конфигурации и локальных файлов Nextcloud |

Рабочие `.env`, `secrets/`, `runtime/` и `backups/` приватные и не коммитятся. Весь `deploy/knowledge/` исключён из Docker build context API. Полные выводы `docker compose config`, `occ config:list --private`, экспортов External Storage нельзя публиковать: они могут содержать пароли.

## Повторное развёртывание на Linux

Перед запуском проверить ресурсы, свободные порты и текущие сервисы. На действующем сервере сначала сохранить конфигурацию Nginx. Не выполнять общий `docker compose down`, очистку Docker или перезапуск VPN/API.

1. Скопировать файлы этого каталога в отдельный `/opt/leader-knowledge` с правами `0700`.
2. Выполнить `python3 prepare.py`. Секреты создаются один раз; повторный запуск их не меняет.
3. Настроить приватный `.env`, домен и реальный адрес доверенного reverse proxy. Не доверять всем приватным сетям.
4. Выполнить `docker compose up -d --wait --wait-timeout 240` только из этого каталога.
5. Передать приватный `.env.knowledge.local` как `secrets/knowledge.env` с правами `0600`. Запустить `python3 configure.py`.
6. Выпустить сертификат, проверить `nginx -t`, включить отдельный виртуальный хост и сделать `systemctl reload nginx`.
7. Проверить `/status.php`, вход и WebDAV через HTTPS, затем здоровье API и неизменность процессов остальных сервисов.

Compose ограничивает ресурсы пилота: PHP 256 MB на процесс, до четырёх Apache workers, Nextcloud 768 MB, cron 384 MB, PostgreSQL 384 MB, Redis 128 MB. Nextcloud рекомендует PHP не менее 512 MB; перед рабочей нагрузкой нужно пересмотреть лимиты по измерениям, особенно для превью/OCR/больших документов. Индексация вынесена в отдельный worker dev API, OCR пока не реализован.

## Сертификат и продление

Внешний HTTP-запрос к домену перехватывается DDoS-страницей, поэтому HTTP-01 не прошёл. Для первоначального сертификата используется DNS-01:

```bash
certbot certonly --manual --preferred-challenges dns \
  --manual-auth-hook 'python3 /opt/leader-knowledge/acme-dns-hook.py' \
  -d cloud.leader-product.ru --cert-name cloud.leader-product.ru --non-interactive
```

Нужную TXT-запись читать из `/opt/leader-knowledge/runtime/dns-challenge.json`. Скрипт проверяет появление значения через два публичных DNS-резолвера. Значение подтверждения не является паролем; после успешного выпуска оно больше не требуется.

**Автоматическое продление пока не настроено:** TXT сейчас добавляется вручную. До истечения сертификата нужно подключить ограниченный доступ к DNS API Beget или устранить перехват HTTP-01. Наличие таймера Certbot само по себе этого не решает. После успешного ручного продления проверить Nginx и выполнить reload. Не отключать проверку TLS в клиентах.

## Резервная копия и восстановление

```bash
cd /opt/leader-knowledge
python3 backup.py
```

Скрипт временно останавливает только cron Nextcloud и включает maintenance в новом Nextcloud. Создаёт приватную папку `backups/<UTC>`: `database.dump`, `files.tar.gz`, `deployment-private.tar.gz`, `manifest.json`. Затем возвращает прежний режим. Читаемость архивов проверяется; полное восстановление этим не проверяется.

**Документы внешнего S3 не входят в этот архив.** Перед хранением рабочих документов нужны независимая копия S3/версий, вынос резервных копий за пределы VDS, расписание, срок хранения и пробное восстановление. Файловые версии Nextcloud не заменяют резервную копию.

Порядок восстановления в изолированную среду:

1. Сохранить текущие данные и секреты, закрепить тот же digest Nextcloud.
2. Поднять отдельную БД и Redis; cron не запускать.
3. Восстановить deployment secrets и каталоги `config`, `data`, `custom_apps`, `themes` в новый том.
4. Восстановить `database.dump` в пустую служебную БД; не применять к БД API.
5. Восстановить отдельную копию S3 в тестовый бакет, заменить привязку внешнего диска; тест не должен писать в рабочий бакет.
6. Проверить владельцев файлов, trusted domains/proxies, доступ и содержимое документов; отключить maintenance, затем запустить cron.

До такой репетиции не считать резервирование принятым для production.

## Откат публикации

Отключить только symlink `/etc/nginx/sites-enabled/leader-knowledge`, проверить `nginx -t`, выполнить reload. При необходимости остановить только Compose-проект `leader-knowledge` командой `docker compose stop` из его каталога. Тома, S3 и резервные копии сохранить. Снимок прежнего Nginx находится в `runtime/nginx-before-knowledge.tar.gz`; не восстанавливать весь `/etc/nginx` поверх новых чужих изменений без сравнения.

## Что следует сделать после пилота

- Автоматическое продление TLS и независимые резервные копии с восстановлением.
- Учётные записи редакторов/проверяющих Nextcloud и согласование прав подразделений.
- Развитие интерфейса проверки отложено пользователем; для пилота используется публикация через папку. Embeddings и гибридный поиск остаются следующими этапами.
- Подключение OpenAI API после получения ключа и выбора модели. Help worker уже поддерживает поиск и выдержки без генерации.
- Подготовка ИИ черновиков по решённым обращениям; публикация только после проверки человеком.

## Каталог и индексатор dev

Контракт, ограничения и проверки: [knowledge-catalog.md](../../docs/knowledge-catalog.md).

Релиз: `/opt/leader-api-dev/releases/knowledge-20261031`. Он использует существующий dev PostgreSQL, но отдельные таблицы `Knowledge*` и новый контейнер `leader_knowledge_worker_dev`. Nextcloud продолжает использовать свою отдельную БД. Индексатор не запускает фоновые задачи основного API и не отправляет сообщения пользователям.

Приватный `knowledge.worker.env` в каталоге релиза содержит только параметры источника и dev `DATABASE_URL`. Исходный `/opt/leader-knowledge/.env.knowledge.worker` содержит только параметры чтения Nextcloud. Пароли не копируются в этот runbook, образ или репозиторий.

Перед применением миграции сохранена копия `backup-before/LeaderAPI_dev.dump` и приватная конфигурация предыдущего API. Проверены читаемость архива и checksum. Восстановление на отдельном сервере ещё не репетировалось.

На данном VDS отсутствует BuildKit. Для этого выпуска TypeScript компилируется на рабочем компьютере из тех же исходников, Linux-зависимости и Prisma client собираются в Docker. В приватном каталоге релиза сохранены `source.tar.gz`, `compiled-dist.tar.gz`, адаптированный `Dockerfile.dev-build` и логи сборки. Стандартный `Dockerfile` репозитория остаётся для CI с BuildKit. При повторном выпуске обязательны новая компиляция и свежие архивы; старые `compiled-dist` не использовать для изменённых исходников.

При откате отключить только новый `knowledge-worker`, вернуть предыдущий образ/окружение dev API из `backup-before/previous.json` и `previous.env`. Добавочные таблицы сохранить: старый API их не использует. Не восстанавливать всю БД поверх новых обращений ради отката кода и не выполнять `compose down -v`.

Перед миграцией обнаружены существовавшие ранее различия Prisma по шести внешним ключам Help. Сравнение со старым работающим образом подтвердило те же 12 SQL-операций; они не применялись. Выполнена только новая добавочная миграция знаний. Полный schema diff dev поэтому не равен нулю; на изолированной тестовой БД новая схема проверена без различий. Этот выпуск не исправляет прежние внешние ключи Help.

## Публикация из папки и поиск в Help

Релиз `/opt/leader-api-dev/releases/knowledge-folder-20261031`, образ `leader-api-knowledge-folder:20261031`. Последний overlay — `compose.help-knowledge-dev.yml` поверх `docker-compose.server-dev.yml`, `docker-compose.server-dev.help-simulator.yml`, `compose.worker-dev.yml`, `compose.review.yml` с профилем `help-simulator` (сохранено имя существующего Compose-профиля, фактический провайдер теперь `knowledge`).

`KNOWLEDGE_HELP_IMAGE` закрепляет новый образ. Меняются только `api`, `knowledge-worker`, `help-assistant-worker`; новый Help worker получает тот же `KNOWLEDGE_ENV_FILE` с dev БД и read-only Nextcloud. Не использовать пароль администратора или S3-ключи. Настройки: `HELP_AI_ENABLED=true`, `HELP_AI_PROVIDER=knowledge`, `KNOWLEDGE_ENABLED=true`, `KNOWLEDGE_PUBLICATION_MODE=folder`.

Миграций на этом этапе нет. До изменения сохранены `backup-before/LeaderAPI_dev.dump` с проверкой читаемости/checksum и приватный inventory старых контейнеров/Compose. Доставка проверяется в изолированной БД без запуска уведомителей; реальная папка проверяется отдельным временным файлом без создания обращений. Инструкция для пользователя — [help-knowledge-pilot.md](../../docs/help-knowledge-pilot.md).

Для отката восстановить прежние образы и окружение именно этих трёх сервисов из `backup-before`, сохранив текущие данные. У прежнего API был образ `leader-api-knowledge-review:20261031`, у индексатора — `leader-api-knowledge:20261031`; точный прежний образ Help worker записан в inventory. Не выполнять `compose down`, не пересоздавать БД и не восстанавливать dump поверх новых сообщений. Отключение `folder` останавливает будущую автопубликацию, но не отзывает уже опубликованные документы.
