# Новая база знаний на сервере 126

Цель: отдельный Compose-проект `leader-knowledge-126` в
`/opt/leader-knowledge-126`, подключённый только к dev API.

Документы хранятся в закрытом бакете `leader-knowledge-126` отдельного RustFS
на **192.168.30.126**. Его S3 endpoint внутри сети проекта —
`http://knowledge-s3:9000`; порты S3 наружу не публикуются. Основной том —
`leader-knowledge-126_s3-data`. Nextcloud подключает бакет как External Storage:
имена файлов читаемые, это не Primary Object Storage Nextcloud.

Nextcloud, его PostgreSQL, Redis, cron, S3 и HTTPS-прокси работают отдельно от
контейнеров приложения. Служебные данные Nextcloud находятся в его собственных
томах. Извлечённые версии, права и полнотекстовый индекс — в таблицах
`Knowledge*` существующей `LeaderAPI_dev`. Старое внешнее хранилище не используется.
Том `leader-knowledge-126_documents` сохранён после первоначальной подготовки;
он не является основным хранилищем S3-документов.

## Доступ

- Портал из LAN/VPN: `https://192.168.30.126:18443`.
- Для доверия TLS импортировать **публичный** `secrets/tls/ca.crt` в доверенные
  корневые сертификаты устройства. Приватный `ca.key` передавать не требуется.
- `knowledge-editor` редактирует документы, `knowledge-admin` управляет порталом,
  `knowledge-indexer` читает ту же папку без права записи и без admin-группы.
- Пароли находятся только в приватном `secrets/`; не публиковать их в логах.
- В приложении: «Помощь → ⋯ → База знаний» или администрирование. Нужны права
  администратора либо `manage_knowledge` и доступ к сервису «Помощь».

В Windows можно подключить новый адрес отдельной синхронизацией Nextcloud. Старую
локальную папку не перепривязывать с удалением файлов. Рабочая структура:
`База знаний/Материалы компании`, `Рабочая область ИИ`, `Архив`.
После обработки документы компании публикуются автоматически; черновики и архив
не участвуют в общем поиске. Индексатор сверяет источник примерно раз в минуту.

По решению пользователя текущее подключение ИИ сохраняется. Каталог и поиск
доступны отдельно; эти настройки не добавляют документы в запросы Bunny.
Не применять `compose.help-knowledge-dev.yml` поверх этого развёртывания:
он переключает провайдера ответов на `knowledge`.

## Подготовка

Скопировать в приватный каталог базовые `compose.yml`, `.env.example`,
`prepare.py`, `apache-workers.conf`, `folders.json` и файлы `*-126.*`,
`local_126.py`, `provision-local-s3.cjs`. Выполнить `prepare.py`, затем настроить
приватный `.env`: источник `company-126-dev`, HTTPS origin выше, loopback-порт
Nextcloud `18126`, `KNOWLEDGE_STORAGE=s3`, закреплённые digest образов Nginx/RustFS.
Сгенерировать отдельный CA и сертификат сервера с IP SAN `192.168.30.126`.
Публичный `ca.crt` должен быть доступен для чтения UID контейнеров (`0444`).
Сильные уникальные S3 credentials задать в `secrets/s3.env` с правами `0600`:
`RUSTFS_ACCESS_KEY`, `RUSTFS_SECRET_KEY`. Старые S3/env-файлы не копировать.

Все команды Compose используют три файла:

```sh
docker compose -p leader-knowledge-126 -f compose.yml -f compose.local-126.yml -f compose.s3-126.yml up -d --wait
```

Создать бакет и проверить приватность через `provision-local-s3.cjs` в одноразовом
Node-контейнере того же образа API: только сеть `leader-knowledge-126_default`,
приватный S3 env и смонтированный скрипт, без env/БД приложения.
Затем `python3 configure-local-126.py` создаёт аккаунты, подключения бакета и
папки, проверяет чтение и запрет записи индексатором. Повторный запуск сохраняет
пароли. При переключении первоначального локального подключения скрипт требует
отсутствия файлов, сохраняет его конфигурацию и оставляет том нетронутым.

В существующей dev-схеме сначала запустить стандартную проверку
`scripts/apply-knowledge-migration.cjs`. Для **пустых** таблиц от прежнего db push
подготовлен `scripts/adopt-empty-knowledge-schema.cjs`: явное подтверждение
`KNOWLEDGE_SCHEMA_ADOPTION_CONFIRM=empty-catalog-only`, штатные подтверждения
dev/имени БД и `DB_ACCEPT_DATA_LOSS=0` обязательны. Скрипт блокирует таблицы,
отказывает при наличии данных, сверяет определение с канонической схемой,
восстанавливает generated tsvector/индексы/ограничения в одной транзакции.
После него обязательны штатная проверка миграции **и нулевой Prisma diff**,
поскольку dev API проверяет схему при старте. Полный `db push` не нужен.

`python3 bind-local-126.py` под общим `deployment.lock` проверяет dev-хост/БД,
сохраняет приватный снимок, добавляет source env и CA в dev Compose и запускает
`leader_knowledge_worker_dev`. Выбранный ИИ-провайдер сохраняется. У индексатора
только dev DB и reader Nextcloud, без S3/ботовых ключей. Базовый Compose сохраняет
подключение при следующих штатных релизах API. Если файл привязки Bunny уже
переопределяет KNOWLEDGE/NODE_EXTRA_CA_CERTS, необходимо проверить согласованность
перед запуском. Ошибка привязки восстанавливает прежний Compose; добавочные
таблицы и документы остаются на месте.

На этом сервере действует `LP_DEV_EGRESS`. Для доступа индексатора разрешается
только dev subnet → текущий IP нового HTTPS-прокси:443 после Docker DNAT.
`allow-dev-egress-local-126.py` не меняет финальный запрет остальных направлений.
Отдельные service/timer поддерживают это разрешение после изменения IP.

## Резервные копии и восстановление

`leader-knowledge-126-backup.timer` запускает копию ежедневно в 03:15 по времени
сервера с небольшим случайным сдвигом. Ручной запуск:

```sh
python3 /opt/leader-knowledge-126/backup-local-126.py
```

Скрипт переводит только новый Nextcloud в maintenance, останавливает его cron,
сохраняет его БД/файлы и отдельную согласованную копию S3-тома при остановленном
новом S3. Дополнительно создаёт dump `LeaderAPI_dev`, архив приватного deployment,
SHA-256 и manifest. Затем возвращает сервисы. Каталог `backups/<UTC>` приватный.
Это локальные копии на 126; независимое внешнее копирование не настроено.
Автоматического удаления архивов нет, свободное место следует контролировать.
`leader-knowledge-126-certificate.timer` ежедневно проверяет срок TLS и продлевает
серверный сертификат тем же CA за 30 дней до истечения.

Для восстановления использовать отдельный тестовый проект/тома: восстановить
`nextcloud.dump` в новую служебную БД, `nextcloud-files.tar.gz` в новый том
Nextcloud, `s3-data.tar.gz` в новый том RustFS. Использовать закреплённые образы,
сохранённые secrets, имена/сетевые aliases и приватную конфигурацию. Cron и
индексатор до проверки не запускать. Проверить чтение контрольного объекта через
S3 и WebDAV. Dev API dump восстанавливать только в отдельную БД для репетиции,
не поверх текущих обращений. Архив `documents.tar.gz` сохраняет первоначальный
локальный том и не заменяет S3-архив.

Откат подключения: вернуть точные сохранённые файлы из `runtime/binding-*`,
пересоздать только dev API/Help worker и остановить новый индексатор. Остановка
портала — только новый Compose-проект. Тома, S3-объекты, очередь и БД сохраняются.
Не выполнять `down -v` и не восстанавливать dump поверх новых обращений.
